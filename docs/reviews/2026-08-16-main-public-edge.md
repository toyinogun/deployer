## Minor
### 🟡 New AC-24 test largely duplicates an existing one, `internal/tunnelwatch/tunnelwatch_test.go:206`
**Problem**: `TestTheTellingDoesNotDependOnTheThingItReportsOn` (new, AC-24) and the pre-existing `TestAnUnreachableEndpointIsAnOutage` (line ~120) exercise the identical scenario: a `New(...)` watcher pointed at `http://127.0.0.1:1/ready`, one `check`, asserting exactly one message sent. The new test adds one extra assertion (the `to` address) but is otherwise a near-verbatim copy.
**Why it matters**: The commit message frames this as "covered incidentally by an untagged test and is now explicit," which is a reasonable rationale for adding an AC tag, but as written it leaves two tests that will always pass or fail together, doubling maintenance for one behavior rather than adding new coverage. A future change to the unreachable-endpoint path only needs one test to catch it; the second one is redundant machinery.
**Suggested fix**: Either fold the AC-24 tag and comment into the existing `TestAnUnreachableEndpointIsAnOutage` (rename or add a `covers: AC-24` line there) and drop the new function, or, if the intent is genuinely to keep the two ACs visually separate in the suite, have the new test assert something the old one doesn't (e.g. that the mail is sent even though the `ready` call errored with a dial failure specifically, distinguishing it from a non-200 response) so the duplication buys something.
